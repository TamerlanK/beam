Privacy

beam moves files between two browsers. This page says what this server sees, what it keeps, and what stays on your device. It is written from what the code does.

Processed in memory only

  • IP address. Used to put devices on the same network into one room and to rate-limit room-code joins. Kept only while you are connected.
  • User-Agent. Read once to pick a phone, tablet, or desktop icon. Only that icon type is kept.
  • Display name and emoji. Sent to the server and shown to the other devices in your room.
  • Per transfer: file name, size, type, and progress.

Previews

When you offer an image or PDF, your browser may attach a small thumbnail so the receiver can see it before accepting. That thumbnail passes through the server unencrypted. Only the file chunks themselves are end-to-end encrypted, with a key the server never has. A relayed transfer then forwards ciphertext the server cannot read.

Encryption needs the Web Crypto API on both devices, which browsers only expose on HTTPS or localhost. If either side lacks it, or the key exchange fails, the transfer falls back to plaintext and a relay server can read the chunks. An encrypted transfer shows a lock and a short code in its row. Compare that code on both devices to check that nobody sits in between.

Logs

The server writes structured logs to its standard error stream. They contain client IDs, display names, IP addresses, file names and sizes, and connection events. They do not contain file contents.

The software does not store logs itself. How long they are kept is decided by the operator of this instance, not by beam. Ask the contact below for their retention period.

Nothing on disk, no cookies

The server writes nothing to disk and sets no cookies. Your device identity (a random ID, name, and emoji), your theme choice, and your transfer history live in your browser's local storage. Clearing site data removes them.

Direct transfers

When two devices connect directly, each browser asks Google's STUN server (stun.l.google.com) for its public address. Google sees your IP address in that request and nothing else. If a direct connection fails, the transfer is relayed through this server.

Acceptable use

  • Do not send content that is illegal where you or the recipient are.
  • Do not run bots, scrapers, or scripted clients against this instance.
  • You are responsible for what you send and to whom.
  • The operator may block IP addresses without notice.
  • Files are never inspected. The server cannot read encrypted chunks and does not look at anything else.
